# 工具行为改写

不改本体一行代码，只在**两个时刻**动手：**请求即将发出的那一刻**，和**工具交回结果的那一刻**。

装上去就有用，不需要任何命令。

## 它做什么

六件事，每件都能在配置里单独关掉：

### 1. 联网搜索只掏段落摘要

DeepSeek 的搜索接口每条结果给了两段：短的（一两百字，就是"这页在讲什么"）和长的（几百到几千字，大页面直接是整篇正文节选）。

本体自带的那个搜索工具掏的是**长的**，一次搜八条就是一万多字进了上下文。这个功能让它改掏**短的那一段**——是换一个口袋拿，不是把长文拦腰砍断。

只动搜索这一个工具，别的工具不碰。

### 2. 会话历史交给助手模型

本体查群聊历史，一次最多交回五十条原始消息，翻页还要模型自己拿着编号一页页往前推，而且**根本不支持按时间查**。真让它翻，能连着翻十几次、几万字塞进上下文，把整个请求撑到发不出去。

开启后：

- 主模型只需要说"要查什么""大概哪个时间段"
- 插件先用一次模型调用把人话时间翻成具体起止
- 直接按时间窗去库里筛（不再靠编号翻页），要跨群就先把待过的群列出来一个个筛
- 筛出来的按条数切块，交给助手模型逐块整理
- **原始消息立刻丢弃**，最后只把一段摘要交回主模型

私聊那边接的是「私聊历史查询」插件的查询入口——它负责写库的部分一个字没动。

### 3. 看不了图的模型也能用视觉回溯

装了「Visual Recall - 视觉回溯」、但主模型是纯文本（比如 DeepSeek 的 pro 型号）时，取图那一步交回来的图片，模型只看到"一个文件路径"。

开启后，图片会先交给本体的「图片转述模型」看一眼，换成文字描述再送进主模型。原图不再往里塞。

主模型本身能看图时，这个功能不起作用。

### 4. 请求体检

每次请求发出去之前，机器过一遍结构：

- 有没有两段够长的内容一模一样（人格被注入两遍就抓这个）
- 工具调用和结果对不对得上（申请了没返回、返回找不到申请）
- 单条是不是太长
- 工具结果占了多少
- 有没有多条系统提示
- 有没有空消息

**只报告不动手**，结果写在抓包记录里，日志里也会打一行。

### 5. 提示词来源追踪

包住每一个"请求时钩子"，钩子前后各拍一张快照，比一比就知道**这次请求里哪个插件往哪儿塞了什么**。

- 系统提示上的改动：抓包页按区间**染色**，每段后面跟一个上标写插件名
- 往用户消息里追加的提醒（很多插件走这条路，不碰系统提示）：在消息里搜到就染色
- 下面挂一个清单：每个插件改了多少字、走的哪个钩子

**追不到本体的拼装过程**——人格、历史、时间提醒这些没有钩子可挂，只能整体当作默认底色。

### 6. 抓包页

插件卡片上的「查看界面」就是它：

- 每次真正发给模型的内容，一条一行，点开看完整
- **谁发起的**：顺着调用栈认出是哪个插件
- 顶部刷新键旁边的方块键：**一键终止所有会话正在跑的请求**（点两次确认）

## 还留着的旧功能（默认关）

插件最早只干一件事：发请求之前把"工具回传"那一段原样搬进一条普通消息，只换身份、不改内容，用来绕开上游"函数名不能为空"的拒收。

配套还有一道轮次闸门：一次提问里工具来回够了就把工具收走，逼模型开口。

这两样现在是**兼容选项，默认关闭**，需要时才打开。其余六个功能不受这个开关影响。

## 安装

- **从压缩包**：把 zip 拖到面板的插件页上传
- **从仓库**：插件页填本仓库地址

装完不需要命令，配置项在插件卡片里。

## 配置

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 联网搜索只掏段落摘要 | 开 | 只动搜索工具，别的工具不碰 |
| 单条搜索摘要最多多少字 | 400 | 兜底用，正常情况接口只给一两百字 |
| 接管会话历史查询 | 开 | 群聊接管本体的工具，私聊接管私聊插件的查询入口 |
| 助手用哪个模型 | 留空 | 留空跟着当前会话走；查历史是重复性活，挑便宜的够用 |
| 最多整理几块 | 4 | 直接决定最多花几次模型调用 |
| 每批整理多少条 | 50 | 筛出来的消息按这个条数切块 |
| 一次最多捞多少条 | 3000 | 按时间窗筛完再封顶；跨群是每个群各自封顶 |
| 让看不了图的模型也能用视觉回溯 | 开 | 转述模型在配置文件 → AI → 通用设置里填 |
| 请求体检 | 开 | 抓包开关关着时不跑 |
| 换掉工具回传的身份 | **关** | 旧功能，需要绕上游拒收时才开 |

## 注意事项

**时间和时区**：数据库里存的是世界时、而且时区信息已经丢掉。插件会按本体配置的时区换算成本地钟点再交给助手模型，跟「私聊历史查询」插件用的是同一套换算，两边看到的时间一致。

**历史入库后来源丢失**：提示词来源追踪只反映**本次请求**里谁加了什么，追不回"这条历史消息当初是谁加的"。

**并发**：多个会话同时发请求时，来源记录取最近一次，极端情况下可能张冠李戴。

**只覆盖开放接口兼容的服务商**：抓包挂在开放接口那一层，所以走兼容协议的服务商（含各类中转站）全都能抓。直连 Anthropic 或 Gemini 原生协议的不在其中。

## 兼容

- 需要 AstrBot 4.20 及以上
- 与「Visual Recall - 视觉回溯」「私聊历史查询」有专门对接
- 所有改动都通过运行时包装完成，不改本体任何文件，卸载后原样还回去

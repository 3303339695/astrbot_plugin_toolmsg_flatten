# 工具回传改写

**只干一件事**：发请求之前，把"工具回传"那一整段**原样**搬进一条普通消息（默认系统侧）。

不套模板、不改格式、不加壳、不改标点——就是把原来那段的身份换掉。

## 安装

三种方式，任选：

- **从压缩包安装**：把 `astrbot_plugin_toolmsg_flatten.zip` 拖到面板的插件页上传即可；
- **从仓库安装**：插件页填本仓库地址；
- **手动**：把整个文件夹放进数据目录下的 `plugins`，重启机器人。

装完不需要任何命令，配置项在插件卡片里。

## 为什么需要它

上游（谷歌那边）的校验严起来之后，工具回传那条如果没有函数名，整条请求被打回：

```
*.contents[N].parts[0].function_response.name: Name cannot be empty
```

严起来之前屁事没有。插件在**发送那一刻**把这条换个身份，它就没东西可挑了。

## 分工（重要）

| 层面 | 谁负责 | 动没动 |
| --- | --- | --- |
| 存进数据库 | AstrBot 原生 | **一个字都不动** |
| 发请求给服务商 | 本插件 | **只换"工具回传"的身份** |
| 工具回传的内容 | AstrBot 原生 | **一个标点都不动**（超长只省略多余部分） |
| 助手的工具申请 | AstrBot 原生 | **原样保留** |
| 工具清单 | AstrBot 原生 | 不动（轮次闸门除外，见下） |
| 提示词 | AstrBot 原生 | **不重写**：重复提醒、收尾提示全用原版原文 |

拿真历史跑出来的对照：

| 原来 | 发送时 |
| --- | --- |
| 助手：49 字 + 一份工具申请 | 助手：49 字 + 那份申请（原样） |
| 工具：400 字回传（`role="tool"`） | **同一段 400 字，原样**，只是身份变成普通消息 |
| 双方后面说的话 | 原样 |

## 末尾的提醒怎么办

AstrBot 会把"重复调用"的提醒**拼在工具回传的末尾**。这属于原版内容，所以：

- 它跟着整段一起搬进去，位置还是末尾；
- 内容太长按下限省略时，先把提醒剥出来、截断正文、再把提醒原样接回去——**提醒不能被截掉**；
- 万一原版没生成（比如换参数不算重复），就按**原版的模板和阈值**（第 3/4/5 次）补一条，措辞不重写。

## 两条上限

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| 单条结果最多带多少字 | 800 | 一条超了截断并注明 |
| 一次往返合计最多带多少字 | 2000 | 并行开五六个工具时压住总量 |

## AstrBot 原生的那套（照抄，不自己编）

改这个插件之前，先把原版怎么处理"多轮工具调用"翻了一遍，记在这儿：

| 机制 | 原版做法 |
| --- | --- |
| 工具结果回传 | 一条 `role="tool"` 消息，和助手那份申请按编号严格配对 |
| 一样的话反复调 | 连着第 3 次给 L1 提醒、第 4 次 L2、第 5 次 L3，提醒直接**拼在工具结果的末尾**交给模型 |
| 步数上限 | `max_agent_step` 默认 30；到上限就**把工具摘掉**，再注入一句收尾提示，最后跑一步 |
| 结果太大 | 超过约两万七千个词的估算量，只留一小段预览，其余写进文件，并附一句"去看文件" |

那几句原文（英文，和工具结果一起出现，模型读得懂）：

```
[SYSTEM NOTICE] By the way, you have executed the same tool `<name>` with the
same arguments <n> times consecutively. Double-check whether another tool,
different arguments, or a summary would move the task forward better.
```

```
Maximum tool call limit reached. Stop calling tools, and based on the
information you have gathered, summarize your task and findings, and reply to
the user directly.
```

**所以原版为什么很少查起来没完**：工具结果是以"配对好的工具消息"身份回到模型眼前的，
模型一看就知道"这是我刚问的那件事的答复"，自然往下走。它并不需要谁在旁边催。

我们这个插件没法保留那个身份，所以：

1. **原地搬，一个字不改。** 工具回传那整段直接放进系统侧，末尾提醒跟着一起走。
2. **重复调用的提醒，一条不少地带着走。** 按字数省略时被切掉的恰恰是尾巴——
   现在先把提醒剥出来、截完正文再原样接回去；万一原版没生成，就按**原版的模板和阈值**
   （第 3/4/5 次）补一条，措辞一个字不改。
3. **到轮次上限时注入原版那句收尾提示**（直接从执行器类里取，不重写）。

## 轮次闸门具体怎么掐

同一句提问里反复调工具是常态（弱模型尤其），光靠嘴劝没用——它答应"不查了"不算数。

所以加了一道闸：数这一句提问里工具已经来回了几轮，**到了上限就把这次请求的
工具清单收走**，再注入上面那句原版收尾提示。

- 没有工具可调，它只能开口；
- 只影响**这一次请求**：存储不动，下一句提问进来计数归零，工具照常给；
- 上限在配置里改（1～12）。
- **为什么不用 tool_choice="none" 代替**：见下一节，这条路在这条链路上不生效。

### tool_choice 实测（别再试了）

| 发出去的值 | 模型这一轮 |
| --- | --- |
| `auto` | 调了工具 |
| `none`（按理该禁止） | **照样调了工具** |
| `required`（按理该强制） | 调了工具 |
| 指定具名工具 | 调了工具 |
| 干脆不带这个字段 | 调了工具 |

五个结果一模一样：**这个参数在中转/上游那一层被丢掉了**。所以想让它这一轮只说话，
唯一管用的办法是把工具清单从请求里拿掉——闸门干的正是这件事。

另外，AstrBot 自己的签名里只声明了 `auto` / `required` 两种，而实际发出去的永远是
`auto`（`required` 那两处调用在源码里是注释掉的）。

### 为什么"重复调用提醒"常常管不住它

原版那三档提醒（第 3/4/5 次）判定的是**同一个工具 + 同一套参数连续调用**。
真查起来的时候，它每一轮换一个搜索词——参数不同，永远不算重复，提醒一次也不会出现。
所以提醒负责"别原地打转"，闸门负责"别无限翻页"，两件事不能互相替代。

## 配置

| 配置 | 说明 |
| --- | --- |
| 启用工具回传改写 | 总开关 |
| 只对这些服务商生效 | 关键字，多个用英文逗号；默认 `gemini` |
| 换成哪一种身份 | `system`（默认）或 `user`，实测都通 |
| 一次提问里工具最多来回几轮 | 到点收走工具清单 |
| 单条 / 合计字数上限 | 超了省略多余部分，防上下文被挤爆 |
| 抓包相关 | 见下 |

## 抓包页面

插件卡片上有个查看界面的按钮，打开就是「接口抓包」页：左边列请求、右边看完整内容，
**两栏各自滚动**（头固定在顶上，整页不跟着滚；翻左边的记录时右边不会跑出视野）。
抓包文件在插件数据目录下的 `api_trace` 子目录，每天一份。排完建议关掉。

## 备份导入与"插件不见了"

导出备份时，整个插件目录会被打包（跳过缓存文件夹和编译产物）；导入时把包里的
「插件」那一层解出来，覆盖到当前插件目录——**覆盖之前，原来的插件目录会被改名成
`plugins.bak`**。

所以如果换到别处导入后"插件没了"，按这个顺序看：

1. 数据目录下有没有 `plugins.bak`：有，说明"旧的被挪走、新的正在解"；
2. `plugins`（正式目录）里有没有这个插件文件夹：
   - 有 → 文件在，问题在加载（去看启动日志里这个插件名的报错）；
   - 没有 → 解压那一步没走完，先看导入完成后的提示里有没有告警。
3. 插件包本身有没有问题：包里应当能看到以插件目录名开头的一串文件（入口、核心、
   说明、配置表、网页三件套、元数据、图标）。

**关于"检测更新"**：这个按钮能否用，取决于"这插件是不是从插件市场装的"。
本插件是手搓的，没有市场来源记录，所以会显示"不是通过市场安装，无法检测或执行更新"。
这跟能不能加载、能不能用**没有关系**；要让它可更新，得先把插件发布到市场（有仓库地址
并进入市场索引），那是另一件事。

## 维护须知

1. **补丁必须当场打**：插件加载得早，那时服务商的类往往还没导入，枚举是空的。
   所以启动时包一遍，每条消息再当场包一遍（两路共用去重集合）。
   典型症状：热重载当天正常，冷启动重启后又开始 400。
2. **热重载要能换掉旧壳**：旧壳闭包引用旧模块的设置，重打补丁时先剥回原件再包。
3. **改写只在发送这一层**：存档是 AstrBot 的事，动它就是动用户的聊天记录。

### 自检清单

| 现象 | 含义 |
| --- | --- |
| 日志有"已当场包装服务商 …" | 补丁生效 |
| 抓包里工具清单照常、且没有 `role: "tool"` 的消息 | 改写生效 |
| 抓包里还能看到 `role: "tool"` | 改写没生效，多半是补丁没打上 |
| 日志有"执行器挂钩失败" | AstrBot 改了执行器名字，要跟着改 |
